# Community Guide

Chrome Pro is intended to grow through real usage and practical contributions.

## For users

The most valuable early contribution is a clear report. Tell us what you were trying to accomplish, what happened, what you expected, and how to reproduce it.

For UI problems, add a screenshot when it helps explain layout or behavior. For performance problems, include measurements when possible.

## For contributors

Good first contributions include:

- fixing a reproducible bug
- improving an empty/error state
- improving keyboard accessibility
- improving documentation
- adding focused tests
- reducing startup or navigation work
- improving search reliability
- polishing a small piece of browser UX

Avoid large rewrites without first explaining the problem and proposed direction.

## Discussion standards

Be respectful, specific, and evidence-driven. Different opinions are welcome. Personal attacks, secrets, credentials, private browsing data, and confidential information do not belong in issues or pull requests.

## How feedback becomes product work

```text
User experience
     ↓
GitHub Issue / feedback
     ↓
Reproduction + triage
     ↓
Roadmap / Redmine planning
     ↓
Focused implementation
     ↓
Review + CI
     ↓
Release
     ↓
User feedback again
```

This loop keeps Chrome Pro grounded in real user needs rather than feature count alone.
