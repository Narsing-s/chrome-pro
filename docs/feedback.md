# Feedback

Chrome Pro is intended to be a user-driven browser project. Feedback is not an afterthought: it helps determine what gets polished, redesigned, or built next.

## Useful feedback

### Bug
Tell us what happened, what you expected, exact reproduction steps, operating system, app version/commit, and relevant logs.

### UX feedback
Describe the interaction that feels confusing, slow, crowded, inconsistent, or difficult. Screenshots are helpful.

### Feature idea
Start with the user problem rather than only the proposed implementation. Explain who benefits and what a successful solution would look like.

### Performance
Include measurements where possible: startup time, memory usage, navigation latency, search latency, or reproducible CPU spikes.

## Privacy

Do not include passwords, API keys, cookies, access tokens, private URLs, personal identifiers, or confidential browsing data in reports.

## What happens next

Maintainers may ask for reproduction details, label the report, connect it to roadmap work, or close it when it is already tracked elsewhere. Thoughtful disagreement is welcome; respectful discussion makes the project better.
