## Documentation rules

- Document **shipped behavior** as shipped.
- Label experimental work clearly.
- Put future ideas in the roadmap rather than presenting them as available features.
- Update the relevant page when code, configuration, commands, or user behavior changes.
- Prefer short examples that a new contributor can copy and run.

## Project status

Chrome Pro is an actively evolving project. The desktop browser and web application are usable foundations, while several advanced browser features remain under development. Reliability, usability, security, and contributor experience are first-class goals.

## Feedback loop

Users can report bugs, UX issues, performance observations, and feature ideas through GitHub Issues. Contributors can propose fixes through pull requests. Redmine can be used for higher-level planning and cross-workstream tracking when a team needs it.
