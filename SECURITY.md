# Security Policy

Security reports should not contain secrets, credentials, session cookies, or private user data.

## Supported versions

Security fixes are prioritized for the latest `main` release and actively maintained release branches.

## Reporting

For a suspected vulnerability, avoid publishing exploit details in a public issue. Contact the repository maintainers through a private GitHub security channel when available.

Include the affected component, impact, reproduction steps, and a minimal proof of concept when safe to provide.

Please allow maintainers reasonable time to investigate and release a fix before public disclosure.
